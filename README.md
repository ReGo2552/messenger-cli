# TCP CLI Messenger

Консольный чат на Go. Клиенты подключаются к одной комнате через TCP. Сервер добавляет ник отправителя и пересылает каждое сообщение остальным участникам.

## Запуск

Для запуска нужен Go 1.27.4 или новее и свободный локальный порт 9000. Склонируйте проект:

```sh
git clone https://github.com/ReGo2552/messenger-cli.git
cd messenger-cli
```

Откройте три терминала в корне проекта и выполните по одной команде в каждом.

1. `go run ./cmd/server`
2. `go run ./cmd/client -nick alice`
3. `go run ./cmd/client -nick bob`

Дождитесь подтверждения входа у обоих клиентов. Введите строку и нажмите Enter.

| Кто вводит | Строка | Что видит собеседник |
| --- | --- | --- |
| Алиса | `Ты здесь?` | `alice: Ты здесь?` |
| Боб | `Да, читаю.` | `bob: Да, читаю.` |

Ctrl+D на пустой строке завершает клиент. Ctrl+C в терминале сервера завершает чат.

## Отключения

У каждого соединения своя очередь на 64 кадра. В сокет пишет одна горутина с дедлайном 5 секунд на кадр. Если очередной кадр не помещается в очередь или запись завершается по таймауту, сервер отключает этого получателя. Остальные участники продолжают переписку.

При Ctrl+C сервер прекращает принимать подключения, закрывает сокеты и ждёт завершения обработчиков, в том числе для клиентов, которые ещё не отправили ник.

## Проверки

- `make test` запускает тесты всех пакетов.
- `make check` запускает `go vet ./...` и тесты с детектором гонок. Эту же проверку выполняет `make` без аргументов.

Без Make выполните `go vet ./...` и `go test -race ./...` из корня проекта. Тесты кодека проверяют границы кадров в потоке. Серверные тесты проверяют доставку сообщений, отключение медленного читателя и остановку с открытыми соединениями.

## Протокол v1

Каждый кадр начинается с шестибайтового заголовка. Следом идут байты тела. Их количество указано в поле длины.

| Смещение в байтах | Поле | Значение |
| --- | --- | --- |
| 0 | Версия | `0x01` |
| 1 | Тип | Однобайтовый код из таблицы ниже |
| 2–5 | Длина тела | `uint32`, Big Endian, от 0 до 65 536 байт включительно |

Тело сообщений чата содержит JSON в UTF-8. Кодек передаёт тело как байты. Разбор JSON относится к обработчику сообщения.

| Код | Тип | Направление | Пример тела |
| --- | --- | --- | --- |
| `0x01` | `TypeHello` | Клиент → сервер, первый кадр задаёт ник | `{"nick":"alice"}` |
| `0x01` | `TypeHello` | Сервер → клиент, подтверждение входа | `{"nick":"alice"}` |
| `0x02` | `TypeMessage` | Клиент → сервер | `{"text":"Привет"}` |
| `0x02` | `TypeMessage` | Сервер → клиент, сервер подставляет ник отправителя | `{"from":"alice","text":"Привет"}` |
| `0x05` | `TypeError` | Сервер → клиент | `{"message":"Ник уже занят"}` |

При чтении кодек отклоняет неизвестную версию и превышение лимита сразу после заголовка. Конец потока между кадрами даёт `io.EOF`, обрыв внутри кадра даёт `io.ErrUnexpectedEOF`. При записи нулевое поле `Packet.Version` выбирает текущую версию.
